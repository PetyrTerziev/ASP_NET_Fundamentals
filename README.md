# ГардПост (GuardPost) 

**ГардПост** е уеб приложение за малки частни охранителни фирми. То заменя електронните таблици, в които ръководителите
планират охранителите си, с едно място за:

- **Обекти** – охраняваните места (складове, офис сгради, магазини) и колко охранители изисква всеки договор;
- **Охранители** – персоналът, удостоверенията и ранговете;
- **Смени** – седмичен график, който **спазва правилата за труд и почивка** (без застъпващи се смени, минимум 12 ч. почивка);
- **Инциденти** – дневник на всичко случило се на обектите – от фалшиви аларми до опити за проникване.

Таблото показва в реално време дали всеки активен обект има достатъчно охранители на смяна, кои смени текат днес и кои
инциденти все още са отворени.

Основни функционалности
 ----------------------------------------
 **Табло** - Покритие в момента за всеки обект (охранители на смяна спрямо изискваните), смените за днес, отворените инциденти, подредени по сериозност, обобщена статистика. 
**Обекти** -Пълен CRUD, търсене по име/възложител/адрес, филтър по град и активност, страниране, страница с детайли с предстоящите смени и последните инциденти, „меко“ изтриване. 
 **Охранители**-Пълен CRUD, търсене, филтър по ранг, страниране, отработени часове за текущия месец, детайли с предстоящите смени и докладваните инциденти, проверка за уникален номер на удостоверение още докато се пише, „меко“ изтриване. 
 **График (смени)** -Пълен CRUD, седмичен изглед понеделник–неделя, филтър по обект и/или охранител, навигация по седмици, бърз избор на продължителност 8/12/24 ч., отбелязване на дневни/нощни смени и на текущите. Бизнес правила: продължителност 1–24 ч., без застъпване на смени на един охранител, поне 12 ч. почивка между две смени, само активни обекти и охранители. 
**Инциденти** -Пълен CRUD, филтър по обект, сериозност и статус, търсене, задължително описание на решението при статус „Решен“. 

При изтриване обектите и охранителите се **маркират като изтрити** (скриват се чрез глобален филтър в EF Core), за да
останат историческите смени и инциденти непокътнати. Бъдещите им смени се премахват, а страницата за изтриване
предупреждава колко смени ще бъдат засегнати.

Архитектура
------------------

```
GuardPost.sln
└── src
    ├── GuardPost.Web               ASP.NET Core MVC: контролери, изгледи, статични файлове, DI (стартов проект)
    ├── GuardPost.Common            константи (ограничения, съобщения, формати), разширения, IDateTimeProvider
    ├── GuardPost.Data.Models       класовете на моделите + изброени типове (без зависимост от EF)
    ├── GuardPost.Data              DbContext, Fluent API конфигурации, миграции, демо данни
    ├── GuardPost.Web.ViewModels    view/input модели, собствени атрибути за валидация
    └── GuardPost.Services.Core     бизнес логика зад интерфейси (ISiteService, IShiftService, ...)
```

Валидация
-----------------
| Поле / правило | Сървър | Браузър |

| Задължителни полета, дължини, диапазони, формати (телефон, удостоверение `ОХ-123456`), имейл | ✔ | ✔ |
| Номерът на удостоверението е уникален | ✔ (контролер + уникален индекс в базата) | ✔ `[Remote]` |
| Краят на смяната е след началото – собствен атрибут `[DateAfter]` | ✔ | ✔ собствен адаптер |
| Дата на назначаване / на инцидент не е в бъдещето – собствен атрибут `[NotInFuture]` | ✔ | ✔ собствен адаптер |
| Описание на решението при статус „Решен“ (`IValidatableObject`) | ✔ | – |
| Смяна 1–24 ч., без застъпване, ≥ 12 ч. почивка, активни обект и охранител | ✔ (`ShiftService.ValidateAsync`) | – |
| Anti-forgery токен при всеки POST (глобален `AutoValidateAntiforgeryTokenAttribute`) | ✔ | – |

 Стартиране
----------------------
Необходимо
----------------------

- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) (или Visual Studio 2022 17.8+ с workload *ASP.NET and web development*)
- SQL Server – достатъчен е **LocalDB** (инсталира се с Visual Studio); работят и SQL Server Express/Developer или Docker

С Visual Studio
-------------------------

1. Клонирайте хранилището и отворете `GuardPost.sln`.
2. Проверете, че стартовият проект е `GuardPost.Web` (десен бутон → *Set as Startup Project*).
3. Натиснете **F5**. При първото стартиране базата `GuardPostDb` се създава, миграциите се прилагат и се зареждат демо данни автоматично.

От командния ред
---------------------------
```bash
git clone <адрес-на-хранилището>
cd GuardPost
dotnet restore
dotnet run --project src/GuardPost.Web
```

След това отворете адреса, изписан в конзолата (по подразбиране `https://localhost:7119` или `http://localhost:5241`).

## Настройки, променливи на средата и потребители

Приложението **няма потребителски акаунти**, затова за локално тестване не са нужни потребителско име и парола.
Единствената задължителна настройка е връзката към базата данни.

| Настройка (`appsettings.json`) | Променлива на средата | По подразбиране | Описание |
|--------------------------------|-----------------------|-----------------|----------|
| `ConnectionStrings:DefaultConnection` | `ConnectionStrings__DefaultConnection` | `Server=(localdb)\MSSQLLocalDB;Database=GuardPostDb;Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True` | Връзка към SQL Server. Използва Windows удостоверяване към LocalDB – без потребител и парола. |
| `Database:ApplyMigrationsOnStartup` | `Database__ApplyMigrationsOnStartup` | `true` | Прилага неприложените миграции при стартиране. |
| `Database:SeedSampleData` | `Database__SeedSampleData` | `true` | Зарежда демо обекти, охранители, смени (±2 седмици около днешната дата) и инциденти в **празна** база. |
| – | `ASPNETCORE_ENVIRONMENT` | `Development` (от `launchSettings.json`) | В Development се показва подробна страница при грешка. |
